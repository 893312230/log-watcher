# ADR-013：阶段四简化——移除 FastText 分类器，RAG 降为两级检索

## 背景

原规划在阶段二引入 FastText（后续升级 DistilBERT 微调）作为 L3 ML 意图分类器，在阶段四引入"BM25 + 向量 + RRF + Cross-Encoder Rerank"三层混合检索。规划审查发现两处过度工程：

1. **FastText 无标注数据难落地**：运维意图分类需要领域标注语料，冷启动阶段不存在；此前代码中的 `L3MLClassifierRecognizer` 实为关键词启发式伪 ML（ADR-011 已将其删除），继续保留 FastText 规划只会再次制造"测试全绿但功能是假"的组件。
2. **三层检索对运维知识库过度**：运维知识库规模有限（文档/Runbook 级别），BM25 + 向量两级检索经 RRF 融合即可达到可用召回；独立 Rerank 服务（bge-reranker-v2-m3）引入额外部署与运维成本，收益不成比例。

## 决策

1. **L3 ML 分类器从规划中移除**：意图识别定型为三层 L1 正则 → L2 关键词 → L4 LLM 兜底（ADR-011）。若未来积累足够标注数据，可作为新层重新引入，届时需先建评测集再上线。
2. **阶段四检索降为两级**：Elasticsearch BM25 + dense_vector 向量检索 + RRF 融合；**Rerank 降级为可选项**，仅在离线评测证明召回质量不足时引入，不作为阶段四验收标准。
3. **安全控制重排**：L3 人工确认的最小版本（SecurityGate + 一次性确认令牌）已在修复期提前落地（ADR-010）；阶段五保留完整四级安全模型（L0 输入过滤 / L1 权限校验 / L2 操作审计 / Prompt 注入防护）。

## 备选方案

- **保留 FastText 规划**：无标注数据，训练目标不存在，放弃。
- **保留三层 RAG 完整规划**：Rerank 服务部署成本高、调参依赖评测集，阶段四范围内不划算，降级为可选。
- **用 PGVector 替代 ES**：与原决策一致保留 ES 首选（运维团队已有经验），PGVector 仍为备选。

## 影响

- 阶段四任务表收缩为：多层记忆 + ES 部署 + BM25/向量两级检索 + RRF + 知识库 ETL；Rerank 与 FastText 不再出现在交付清单
- 阶段五安全范围不含"人工确认"（已前置），聚焦 L0-L2 + 注入防护 + 限流 + 可观测性
- 若阶段四检索效果不达标，按评测数据决定是否引入 Rerank（此时需新增 ADR）
