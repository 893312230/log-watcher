# ADR-011：意图置信度体系重设计（含 L3 伪 ML 分类器移除）

- 状态：已采纳
- 日期：2026-07-22
- 关联：agent.md 阶段二；ADR-009（框架迁移后基线）

## 背景

原四层意图识别（L1 正则 → L2 关键词 → L3 "ML 分类器" → L4 LLM）的置信度体系整体失效：

1. **L1 固定 0.85 恒短路**：所有规则命中即返回 0.85，且兜底正则 `.*(查询|查看|当前|状态...).*` 几乎吞噬一切输入，L2/L3/L4 实际不可达。
2. **L2 评分过低**：命中率线性映射后置信度约 0.09，永远达不到 0.6 阈值。
3. **L3 是伪 ML**：`L3MLClassifierRecognizer` 名为机器学习，实为关键词启发式打分，无任何模型，属于误导性实现。
4. **L4 丢弃真实置信度**：硬编码 0.75，忽略 LLM 实际把握程度。
5. **加权投票不可比**：各层置信度语义不同（常量 vs 评分 vs 硬编码），`ConflictResolver` 的加权混合没有数学意义。

## 决策

### 1. L1 分层置信度

- 具体规则（明确的操作/告警模式）：**0.9**，可短路（阈值 0.85）。
- 宽泛兜底正则（查询类泛匹配）：**0.4**，不参与短路，仅作为弱先验继续向下传递。
- 未命中：0.2。

### 2. L2 评分映射

`confidence = min(0.3 + 0.5 × hitRate², 0.79)`，严格位于 L1 宽泛（0.4 附近的弱信号区）与 L1 具体（0.9）之间：满命中封顶 0.79，保证 L2 永不压过 L1 具体规则，又明显高于无信息先验。

### 3. 移除 L3 伪 ML 分类器

删除 `L3MLClassifierRecognizer` 及其测试。理由：

- 无标注数据，FastText 分类器在阶段四也无法落地（规划同步简化，见 ADR-013）。
- 伪 ML 实现给评审与维护者传递错误的架构信号。
- 语义级分类需求由 L4 LLM 兜底覆盖，L3 的增量价值为零。

Pipeline 收敛为三层：L1 正则 → L2 关键词 → L4 LLM。

### 4. L4 使用 LLM 返回的真实置信度

- Prompt 外置到 `resources/prompts/intent-l4.txt`（含头部注释：用途/输入变量/期望输出），要求 LLM 输出单行 JSON `{"intent":"...","confidence":0..1}`。
- 解析真实 confidence；JSON 置信度字段缺失或越界时回退 0.5；无法解析 JSON 时降级为关键词匹配（0.4 = 0.5 × 0.8 折扣）；LLM 调用异常返回 UNKNOWN（0.1），保证 Pipeline 不中断。
- 用户输入用字面占位符 `${userInput}` 替换，避免 `String.format` 的转义陷阱（模板中多处占位符会导致 `MissingFormatArgumentException`）。

### 5. ConflictResolver 权重重标定

层权重 L1=1.0 / L2=0.7 / L4=0.9，归一化加权平均。权重排序反映各层可靠性：L1 具体规则最可靠，LLM 次之，关键词词频最弱。重标定后各层置信度语义统一（均为"该层对自己结论的把握"），加权混合具备数学意义。

## 后果

- 正面：置信度跨层可比，短路路径真实可达（L1 具体规则命中即返回，省去 LLM 调用）；意图体系可解释、可单测。
- 负面：三层链路在低质输入下更频繁落到 L4，LLM 调用成本略升——这是用成本换正确性的有意取舍。
- 测试：L1/L2/L4/ConflictResolver/IntentPipeline 测试全部按新置信度语义重写。

## 备选方案

- **保留 L3 占位待阶段四实现**：否决。伪实现比缺失更有害；阶段四若引入真实分类器，将作为新组件按相同置信度契约接入。
- **L1 单一 0.85 阈值不动、只修 L2/L4**：否决。宽泛兜底吞噬输入是短路误触发的根源，必须分层。
